## 背景
技术博客是开发者获取信息的重要渠道，良好的排版和样式直接影响阅读体验。当前博客使用JBake静态生成，使用Bootstrap 5.1.3 + 自定义CSS的架构。

## 目标 / 非目标
- 目标：
  - 提升基础字体大小到现代标准（16-18px）
  - 优化行高以适应中文阅读
  - 改进字体堆栈，使用系统字体
  - 优化代码块和内联代码样式
  - 增强移动端响应式设计
  - 改进段落间距和整体排版密度

- 非目标：
  - 不改变网站整体布局结构
  - 不替换Bootstrap框架
  - 不添加新的CSS框架或工具
  - 不改变内容组织方式

## 设计决策

### 1. 字体大小策略
**决策**：将基础字体大小从当前大小（~14-15px）提升到16px，移动端18px

**理由**：
- 现代网站标准：主流技术博客（Medium、Dev.to、CSDN）基础字体16-18px
- 中文可读性：中文文字较小，需要更大字号
- 无障碍友好：符合WCAG 2.1 AA标准最小字体要求

**备选方案**：
- 仅调整标题大小 → 拒绝，基础文本才是核心
- 使用rem单位 → 考虑，但需保留px作为基准

### 2. 行高优化
**决策**：正文行高设置为1.7，标题行高1.3-1.4

**理由**：
- 中文阅读舒适度：1.6-1.8是中文阅读最佳行高
- 段落分隔：无需过多空行即可清晰分隔
- 技术内容：代码和文字混排时行高很重要

**备选方案**：
- 统一行高 → 拒绝，不同元素需要不同行高
- 更小行高 → 拒绝，影响可读性

### 3. 字体栈改进
**决策**：使用系统字体栈，优先使用系统UI字体

**新字体栈**：
```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
```

**理由**：
- 性能：无需加载Web字体，加载更快
- 体验：系统字体在各自平台上最舒适
- 中文支持：明确指定中文字体优先

**备选方案**：
- 引入Web字体 → 拒绝，增加加载时间和带宽
- 仅使用中文字体 → 拒绝，国际化支持差

### 4. 代码块样式现代化
**决策**：
- 增加内边距（16px → 24px）
- 使用更现代的配色
- 增加圆角和阴影
- 改进字体（保持等宽，增大字号）

**理由**：
- 开发者体验：代码是技术博客的核心内容
- 现代审美：扁平化设计，但保留适度阴影
- 可读性：更大空间和更好的对比度

### 5. 移动端优化
**决策**：
- 移动端字体放大（18px基础字体）
- 增加触摸友好的间距
- 优化代码块横向滚动

**理由**：
- 移动优先：60%+流量来自移动端
- 触摸体验：移动设备阅读距离更近
- 实用性：代码在小屏幕上更难阅读

## 风险 / 权衡
- **风险**：样式调整可能影响现有页面布局
  - **缓解**：渐进增强，逐步应用样式

- **权衡**：字体大小增加可能减少单屏信息量
  - **理由**：可读性优先，信息量 vs 阅读舒适度的平衡

- **权衡**：系统字体在不同平台显示差异
  - **理由**：原生体验更重要，一致性通过CSS而非字体保证

## 实施计划
1. 创建新的CSS文件覆盖样式（避免修改原有框架）
2. 逐步应用：先字体和行高，再间距和代码块
3. 响应式测试：桌面端、平板、手机全平台测试、
4. 性能检查：确保CSS文件大小合理
