## 本期速览

- earendil-works/pi: **Anthropic message threads 落地（#11545，11-03 合并）**——会话在服务端保持上下文，请求只发新增消息、让服务端从上一次的回复继续；仅对 `api.anthropic.com` 的 `anthropic` provider 默认开启，gateway 可用 `compat.supportsMessageThreads` 覆盖。**"每轮重发整段历史"这条默认路径第一次有了服务端替代方案**，缓存与 token 账本的算法前提被改写。
- earendil-works/pi: **仓库里出现 `apps/p2`**（README 首行即「EXPERIMENTAL / p2 is a prototype. It will be gone soon.」），一个用独立 [Chord](../../packages/chord) 插件搭的自托管 Pi Durable UI：owner 拥有 agent 与 shell 完全控制权，访客侧 TUI facet 跑在访问者机器的受限 worker 里。同时 Chord 本体新增 **live queries（`self.query`）** 与 i18n（messages / languages）。
- earendil-works/pi: **grep 工具不再自己读文件**——`context` 改为直接取 ripgrep 的 `--context`（#11705），修掉了"8 个约 95MB 日志文件 + `context:2` 十分钟内 OOM"的问题；这是 **breaking**：`GrepOperations.readFile` 被移除，远程执行需自行 override `execute()`。
- earendil-works/pi: **MCP 的 `maxMessageBytes` 现在也管 Streamable HTTP 的 JSON 分支**（#11749）——之前只有 SSE 回复查大小，纯 JSON 回复走 `response.json()` 全量缓冲无上限；同一个超大消息用 SSE 会被拒、用 JSON 能通过。SSE 流超限时也会被取消（#11735）。
- anomalyco/opencode: **27 个合并 PR 呈现清晰的两条主线**——Aiden Cline 一人完成 AI 层的"按 role 拆分 Message、headers/fetch/timeout 全局共享、文件入参接受 bytes/URL/string"重构；Luke Parker 连续 6 个 PR 扩 GUI 插件的 `ctx.ui`（settings rows / selects / menu rows、面板尺寸、插件自带配色主题），补的是第三方插件此前只能手抄私有 markup 的缺口。
- anomalyco/opencode: **compaction 出现一组新的正确性缺陷**——#61371（裁剪以"整个 exchange"为单位，一次性把该 exchange 内全部 tool output 压到 2000 字符，窗口大部分闲置）、#61372（`estimatePrompt` 只按 provider 匹配实测锚点，换模型后仍沿用上一个模型的 token 数）、#61346（provider 返回 503 或只发 SSE keepalive 时 `/compact` 静默挂起 90 分钟，无报错无重试提示）。
- anomalyco/opencode: **免费额度与模型列表的问题仍在扩大**——#61409（免费模型每日额度重置后仍被拒）、#61497（`opencode/crouton-alpha-free` 报 "requires an end-user identifier"）、#61481（Windows 11 上 2.2.4 与 2.2.5 的模型列表全空，重装 7 次无效）。open issues 从 3746 涨到 **3990**。
- vectorize-io/hindsight: **v1.2.0 发布 + Hindsight Models 三个自研模型同时公开**——`hs-decide-1-flash`（decision model，接管 consolidation / reflect / knowledge page 里的小判断）、`hs-rerank-1`（成为默认 reranker，替代 cross-encoder/ms-marco-MiniLM-L-6-v2）、`hs-embed-1`；官方口径是 memory **便宜 2.5x、快 2x**，decision model 单次请求中位 167ms（LLM 调用是 1–7 秒）。decision model 可按请求或按 bank 开启 recall 的 prune / dedup。
- vectorize-io/hindsight: **"强制 tool calling" 被替换为"每次工具调用走 response schema"**（#6176），修的是自托管模型忽略 forced tool choice 时 reflect 直接失败；同时 reflect 的 done/expand 非 list id 字段改为按工具错误处理而不是整体失败（#5952 / #5954）。
- agegr/pi-web: **v0.15.0 发布**——运行中可切模型（从下一次请求起生效）、侧聊标签随主会话恢复、右侧面板标签可拖动重排、扩展 UI 拿到 pi 的 ANSI 调色板；修复了 pi 1.5.0 升级后 HTML 导出全部失败（`sortChildren expected 1 match, found 0`）与 ChatGPT 登录"requires a device ID"。
- 跨仓库: **"上下文从哪来"正在成为三家共同的主线**——pi 用 Anthropic 服务端 threads，opencode 在修 compaction 的裁剪与跨模型锚点，hindsight 用 decision model 替 LLM 做判断；同期三个仓库都出现了**子 agent 与主 agent 互相踢掉缓存**的同类报告（opencode #61318）。
- 跨仓库: **供应链收紧是可观测的跨仓库动作**——pi-web Docker 改用 `npm ci --ignore-scripts` 并有 issue 建议再加 `--min-release-age=3`（#1523）；pi 修掉 Nix 打包缺 pi-schema 导致的 fail（#11682 的后续）；hindsight 的 Hermes CI 改成"按用户的方式安装 Hermes 与插件"。

## 跨项目观察

1. **"上下文放在哪里"成为本期的主线，且三个项目给出了三种答案。** pi 选择把会话状态交给服务端（Anthropic message threads，请求只发增量）；opencode 选择把上下文裁剪逻辑修对（compaction 以整个 exchange 为单位裁剪、换模型后仍沿用旧模型的实测 token 数）；hindsight 选择把判断从 LLM 手里挪到一个 167ms 的专用模型。三者都在同一周内动了同一件事：**降低"每轮都要重新解释自己"的成本**。

2. **子 agent 与主 agent 的缓存互相踢掉，已经在两个仓库里被独立报告。** opencode #61318 观察到同 provider 同模型前缀下主 agent 与 subagent 互相 evict cache，换模型则不复现；上一期 pi-web 为保住缓存专门保证工具顺序与 pi CLI 一致。**会话亲和（session affinity）正在从性能调优项变成架构约束**，而当前的 provider 缓存键设计并不为多 agent 并发准备。

3. **子 agent 已经不是"附属功能"，而是各仓库独立演进的一层。** pi 让 MCP 工具只暴露给 code mode（#11545 同批的 p2 改动）；opencode 加了实验性的 job list endpoint 并把 Console 配置与 skill 下载跨项目共享（#61188）；hindsight 的 Hermes 补了 daemon 数据库路径、keep-alive 失效重试、控制面反代下的版本探测。**这层的问题域正在与主 agent 分化**——主 agent 的问题是模型调用质量，子 agent 的问题是进程、连接与文件所有权。

4. **供应链收紧从"声明"变成"构建动作"。** pi-web 的 Docker 改用 `npm ci --ignore-scripts`，并有 issue 建议追加 `--min-release-age=3` 与 `--allow-git=root`；pi 修 Nix 打包缺 pi-schema；hindsight 的 Hermes CI 改成按用户的方式安装。**三个项目都在窗口期内至少动了一次"安装期脚本"的开关**——这是 agent 生态开始被当作供应链组件看待的迹象。
