## 跨项目观察

1. **AI 层的对外接口正在被逐个仓库重写，方向高度一致。** opencode 把 tools 数组化、参数改名 `input`、structured output 并入 `generate/stream/loop` 的 `schema` 选项、provider 方法具名化，并开始接受 Standard Schema；pi 同期推出不依赖 `eval` 的 pi-schema。两家的共同点是把「结构化输出 / 工具入参」从各家自定义收敛到 **JSON Schema 这条公共轨道**，只是节奏不同：opencode 先改 API 形状，pi 先造校验实现。
2. **session affinity（会话亲和）与 prompt cache 命中第一次同时出现在三个仓库的问题列表里。** pi #11639 给 `openai-responses` 补 `session-id` 以对齐 Codex；hindsight #6244（每批 `fact_ids` 枚举撑破缓存前缀）与 #6243（缺 `session-id` 亲和，`cached_tokens=0` 存成 NULL）；外部同期把这事产品化——Vercel AI Gateway 上线 Sessions 视图，按 session 分组请求、展示 cache hit 与 affinity 路由。**agent 客户端开始关心「这一轮打在哪个账号、哪台机器上」，而不只是「这一轮说了什么」。**
3. **凭据与 token 刷新的并发正确性同时出现在 opencode 与 pi。** opencode #60944：MCP OAuth refresh 跑在 per-credential lock 之外，轮换 refresh token 时第二个连接会重放旧 token、拿到 `invalid_grant`、进而删掉共享凭据；pi #11636：一次失败的 OAuth refresh 会让请求失败，而本地 token 其实仍有效。两边都在修「agent 代理第三方登录态」引入的并发债——凭据锁从各家内部实现变成了公共正确性问题。
4. **无人值守执行从「功能」变成「可靠性工程」。** opencode 给 schedule 补上五种后台 action、attention 级别与运行台账；pi 的调度器被报出跨进程重启后死锁（#11635），同时 pi 侧补齐外部限制清单（Windows conhost、tmux 颜色回显泄漏）；pi-web 补子代理 run 的记录与短 id 命名（#1473、#1474）。**「定时任务」在 agent 产品里正在变成一等公民，而不是插件作者自己搭的 hack。**
