## 本期速览

- **anomalyco/opencode: v2.1.4 的主线是「MCP 交互表单终于能出现」+「compaction 移到后台」**——MCP elicitation 表单在 TUI / Desktop / Web 三端都能弹出（#58184 / #58305），此前工具调用会一直等到超时；新增 `experimental.background_compaction`，在会话接近压缩阈值时提前后台准备摘要；compaction 超出 provider 限制时优先缩短旧 tool output（#58015）；ChatGPT 登录的 context caps 从硬编码拆成可关闭的独立插件 `opencode.provider.openai-context-caps`（#58194）。
- **opencode 同日撤回 Console 托管语音**——#58461 revert 了 v2.1.3 引入的 Console 托管 GPT-Live，理由是语音模型将变成 models.dev 上的普通 provider 模型（#58458 把 realtime / embedding / reranking 模型从目录中剔除）。**托管平台作为特殊通道正在被收回**。
- **opencode 一天内铺开 5 条图像生成接入**——Alibaba、Cloudflare Workers AI Run API、Vercel AI Gateway，外加「可移植图像形状（aspect + resolution）」（#58528 / #58383 / #58387 / #58469），并修掉「OpenAI-compatible host 不返回 output_format 时无法识别图像类型」（#58475）。
- **hindsight 修掉一个被忽视的 prompt cache 杀手**——#6053 把 memory block 从 system prompt 移到 user message，因为该 block 每轮都在变，放在 system prompt 里每次请求都破坏缓存前缀（fixes #5914）；同窗口新增 `operation runs` 扩展点（#6048），记录每次 retain / recall / reflect / consolidation 的墙钟时间与其模型调用、store 调用。
- **ACP 的子代理 RFD 从「文档讨论」进入「协议改动」**——#2465 让 session message 的收发两侧视图互相指名（`senderMessageId` / `recipientMessageId`），并把消息身份从 chunk 上剥离；#2468 定义子代理配置的只读快照（复用 `config_option_update`，不新增协议字段）。**这直接推翻了上期「协议本体零改动、子代理委派未进入规范」的判断。**
- **MCP 成为四个仓库的共同故障面**——opencode 修了 MCP 表单不出现、OAuth 回调被无关请求打断、远程 MCP 请求被 Bun fetch idle timeout 掐断、初始 reconciliation 重复启动 MCP server；pi 在 [Unreleased] 里让 MCP sign-in 只接受 `http:` / `https:` 的 OAuth URL（此前可传 `file:` 或自定义协议）。
- **pi 的 Chord 子系统在长出「可被观察的值」抽象**——`Watchable` / `NativeWatchable` 与共享 watch-handle 实现落地（Mario Zechner），Durable 直接复用；加上 MCP OAuth URL 校验、device-code 登录自动开页/复制码、`/model` 与 `/resume` 搜索排序修复、HTML 导出白屏修复。
- **pi-web 连续第 4 天零 commit，但 issue 侧照常进流**——新开 5 个 issue + 2 个 PR，其中 #1393 明确要求把打包的 Pi SDK 从 **1.2.0 升到 1.4.0**（仓库已落后两个 minor 版本）；#1395 报告长任务下子进程不回收导致整机卡顿。open issues 45 → 51。

3. **托管平台正在被收回为「普通 provider」，方向由 opencode 单方面给出但影响面超出它自己。** opencode 在 24 小时内两件事连着做：#58458 把 realtime / embedding / reranking 模型从目录里剔除、#58461 撤回 Console 托管的 GPT-Live，理由是「语音模型将成为 models.dev 上的普通 provider 模型，Console-only 通道不值得保留」。**背景是 10-17 披露的 Console 泄露事件（约 1.4% Console 用户的 provider key 可能已暴露，且从 Console 删除 key 不等于吊销）。** 同一时间 ACP 的 registry 与 RFD 侧在补「谁来托管、谁能看到」的规范缺口，hindsight 则在给「操作级别」的模型与 store 调用做审计——**三个仓库从不同角度收敛到「中间人持有密钥」这同一件事。**

4. **子代理从「文档提案」进入「协议改动」，这是 ACP 与 pi 的方向性分岔。** ACP 的 `subagents.mdx` 在本期被改了两处并写进 unstable schema：跨 session 消息的双视图关联（#2465）与只读配置快照（#2468），作者栏已是 Vadim Briliantov 与 Ben Brandt 两位核心维护者，文件已 72 KB；pi 侧的对应物不是协议而是内部抽象——`Watchable` / `NativeWatchable` / 共享 watch-handle（Chord 层）与 Durable 的复用。**一个在把子代理标准化进 wire protocol，一个在把「可被观察的值」标准化进存储层；两边都在解决「父子会话之间的状态如何被第三方看见」，但落点一个在协议、一个在实现。**

5. **「长时运行」的宣称正在遇到资源回收与版本滞后两类现实检验，且都落在 pi-web 上。** pi-web 的 #1395 报告子进程不回收导致整机卡顿，#1401 报告二进制文件被当文本预览；更结构性的是 #1393——仓库把 7 个 `@earendil-works` 包精确 pin 在 **1.2.0**，而上游已到 **1.4.0**，**跨过了 v1.4.0 那个改写 compaction 上限的版本**。**hindsight 同期则在修「长时运行的记忆系统如何不被并发写坏」（#6052、官方博客《Thirty Agents, One Memory》）。同样是长时运行，harness 侧在补一致性，界面侧掉队。**

6. **仓库活跃度的差距在本期继续扩大，但「谁在写什么」呈现两种清晰的分工。** opencode 24 小时内 60 commit / 92 个 PR 合并，是唯一有新 release 的仓库；pi 30 commit / 17 个 PR 合并且无 release；hindsight 51 commit 但其中约 20 个是依赖锁文件升级；ACP 9 commit 中 5 个是 registry 同步；pi-web 0 commit。**值得注意的是 opencode 内部的作者分工已经稳定成型——一个作者独占 provider 与图像生成广度，另一个独占 v2 文档重写，两者互不干扰，这比「一个人一天写 20 个 commit」更难被单点接管打断。**
