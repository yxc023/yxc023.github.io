**三个被推入 Active 的 RFD（内容来自 `docs/rfds/`）：**

- **Subagent Sessions**（作者 Vadim Briliantov、Ben Brandt）: agent 委派的子代理各自成为一个 **ACP session id**，其消息、思考、计划、tool call 与当前工作可独立于父 session 展示；父子关联通过 upsert 式的 `subagent_update` 建立，子事件自动沿同一连接流动；session 间消息用 `session_message` upsert 与 `session_message_chunk` 通知。**关联不是一次性任务，父 session 可以在子代理结束后再次给它派活。**
- **Client-Provided System Prompt**（作者 @wpfleger96，Champion @benbrandt）: 补上 ACP 一直缺失的「客户端下发 system 级指令」——agent 在 `initialize` 时声明 `systemPrompt` 能力，`session/new` 接受可选 `systemPrompt` 对象（`mode` + `content`，content 为 `ContentBlock[]`，文本为基线），并像 `cwd` / `mcpServers` 一样在其它 session 生命周期请求中重发。两种模式：**append**（客户端指令追加到 agent 自身指令）与 **override**（替换 agent 内置默认指令，由 `override` 子能力开关控制）。
- **MCP-over-ACP: Stateless MCP Requests over ACP**（作者 @nikomatsakis）: client 或 proxy 用 `"type": "acp"` 声明一个 MCP server，然后直接向其 `serverId` 发独立 MCP 请求；结果、请求级通知与取消都走 ACP，无需第二个进程或网络端点。**只针对 MCP 2026-07-28，不模拟旧版 MCP**；三个身份分层：`serverId`（声明的 server）、`requestId`（调用方生成的内层 JSON-RPC id，跨 proxy 保持）、外层 JSON-RPC `id`（单跳内编号，proxy 可重编）。
