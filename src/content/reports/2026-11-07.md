## 本期速览

- anomalyco/opencode: **发布 v2.2.6**，主打 **Shared MCP Connections**（`pool: true`，把同一 server 上多个目录对同一 MCP server 的重复连接合并成一条）——PR 原文给的数字是「10 个目录 = cloudflare 10 条连接 + 10 份 3,765 个工具的拷贝、cua-driver 10 个进程 189 MB」。
- anomalyco/opencode: **Code Mode 从解释器换成字节码 VM**——`packages/codemode/src/vm/` 落地 **16,754 行**自包含 VM（编译器 / 栈式 VM / 对象模型 / Effect Driver / 预编译 prelude），默认仍是 `legacy`，通过 `experimental.codemode_vm` 切换；**dev 构建已默认打开**（#62444），并暴露 VM 的 suspendable program API（#62413）。
- anomalyco/opencode: **官网 opencode.ai 正式切生产**（#62350 / #62352），旧 Console 里的站点与自定义域名管理被移除（#62388 / #62381），V2 docs 改由站点自己 serve 在 `/docs`（#62389）。
- anomalyco/opencode: **一批安全收紧**：server 的文件读取改为一律 `content-disposition: attachment` + `nosniff` + sandbox CSP，跨站导航打到 `/api/*` 直接 403（#62422）；webfetch / Code Mode `fetch` 拒绝带凭据的 URL，并对每次重定向重新匹配权限规则（#60502 / #61701 / #62373）。
- earendil-works/pi: **p2 的「detail」分级正式落地**——`settings.json` 的 `detail` 1–4 级决定一turn 里聊天区显示多少（thinking / Note / 工具调用折叠到转盘 wheel 与 sheet），先按默认 3 发布，随后 `detail 2` 成为默认。
- earendil-works/pi: **工具的「长相」开始由插件拥有**——code mode 的调用与工具的 TUI 卡片都从插件来（coding-tools / powershell / codemode），core 只保留 `ToolActivity.nestedCalls` 这类取数接口；同时新增 TUI 里的 **projects**（按项目分组会话、`/move` 跨机器迁移）。
- agegr/pi-web: **连续第三天零提交**（最近 push 停在 11-04），但社区侧仍有 3 个新 PR（复制文件全文、Stop 中止后恢复排队消息、标注本轮加载了哪些 skills）和 1 个「多实例 hub」需求 issue（#1577）；open issues 43 → 47。
- vectorize-io/hindsight: **一次密集的数据库性能清扫**（41 个合并 PR）——scoped 实体查询只读要的那几个实体（#6410）、共享同一 filter 的分页只查一次（#6407）、删文件夹不再逐节点重扫整个 bank（#6398）、VectorChord BM25 查询每次检索只构造一次（#6373）。
- vectorize-io/hindsight: **记忆写入前可被扩展拦截**——新增 `filter_retain_facts` / `filter_consolidation_actions` 两个 `OperationValidatorExtension` 钩子，扩展可以在 embedding 与落库之前丢弃或改标签的记忆（#6400 / #6386）。

## 跨项目观察

1. **「共享 / 池化」替代「每会话一份」成为本期的主线改动。** opencode 让同配置的多个项目共享一条 MCP 连接（#61185，给出的量化依据是连接数与 3,765 个工具的重复拷贝）；hindsight 让 query 与 passage 走各自的 embedder（#6380）、共享同一 filter 的分页只查一次（#6407）、BM25 查询每次检索只构造一次（#6373）；pi 把工具调用折叠到转盘、把渲染交给插件（#49b8805）。**四个仓库的优化方向一致：把「重复 N 次的工作」压成 1 次。**

2. **失败模式从「崩」转向「卡住 / 静默失效」，这成了最集中的问题面。** opencode：远端 MCP 一次 DNS 抖动后被永久标记 failed 且无重试（#62369 / #62405）、OAuth 过期直接 403 而不提示重签（#62372）、首个 prompt 拿不到刚连上的 MCP 工具（#62454）、Console 接受连接却不回答导致启动挂起（#62404）。hindsight：embeddings 后端故障时 recall 无降级路径（#6424）。pi：pi-durable 1.5.0 的任务卡在 waiting / completing（#11892）。**这些都不是崩溃，而是"看起来还活着但已经不干活"的状态，上游的监控与重试语义明显落后于功能扩张速度。**

3. **成本可见性正在被当作产品功能来做。** hindsight #6422 报告 per-turn soft-path schema 让 reflect 的整段对话重新计费；opencode 的 session warming 配置新增按 cache TTL 自动决定的 `interval: "auto"`（#60025 / #60969），同时 #62401 报告第一次 warming turn 就是全量 cache miss、#62374 指出统计面板的 "Usage" 显示的是 context 占用而不是账号用量。**"这次调用花了多少钱、为什么没命中缓存"正在从运维问题变成终端用户可见的界面。**

4. **并发与资源占用第一次成为社区提 issue 的主要理由。** hindsight 本期有三条相关报告：文档 PATCH 的策展在 API pod 同步执行、批量编辑会升级为全 fleet 事故（#6418）；`enqueue_graph_maintenance` 的行锁贯穿整个 retain/edit 事务，同 bank 并发写会排队并耗尽连接池（#6417）；`count_unconsolidated()` 每次作业 seq-scan `memory_units`（#6415）。**上一期社区还在报功能缺失，本期已经开始报"服务在并发下不成立"，这是系统进入生产化阶段的典型特征。**

5. **前端形态是三个仓库真正的竞争面，且方向相反。** opencode 走"插件作为扩展位"：GUI plugin 可以贡献主题、代码块 action、原生 settings / menu 组件，桌面端补了移动端 composer dock 与未读会话分组；pi 走"UI 完全交出去"：工具的 TUI 卡片与 code mode 调用全部来自插件，core 只留取数接口；pi-web 则停在"需要多实例 hub 才能用"的阶段。**opencode 在赌生态宽度，pi 在赌核心极简 + 扩展承接，pi-web 三天零提交说明它更像是个人项目的节奏。**

6. **协议层与记忆层都在从"记录"转向"审核"。** ACP 把 client system prompt 从 Preview 推入稳定，并附上 trust guidance 与 prompt injection 说明（#2765）；hindsight 让扩展能在 embedding 与落库之前丢弃或改标签的记忆（#6400 / #6386），但文本不可改。**两者都承认"写进来之前需要有人把关"，并且都把把关权交给扩展而不是核心配置。**
