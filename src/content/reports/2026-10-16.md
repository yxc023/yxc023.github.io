- **agentclientprotocol/agent-client-protocol**: **#2404 提议的 `prompt_suggestions` 明确把「用户仍是 transcript 里每条 prompt 的作者」写成规范。** 接受建议**只填入 composer、绝不发送**；空列表撤回报价；**不得出现在 replay 或 `session/load` 里**；一轮以无建议结束是正常的，Client 不得等待。与 notices RFD 不同，它**没有 fallback 通道**——v1 用 `ClientSessionCapabilities.promptSuggestions` 门控，理由是「让 Agent 判断向模型要一次预测是否值得」。

## 跨项目观察

1. **主题从「声明与生效不符」下沉了一层：这期不再是元数据冻结，而是「同一个名字在不同地方解析成不同的东西」。** 上期的形态是 opencode 的 V1 冻结 schema 把合法 V2 配置标错、pi 的 Windows 默认端口落在 Hyper-V 保留块。本期同一机制的新形态有四例，且全部发生在**provider / model catalog 这一层**：pi 内置 `kimi-coding` provider 说 Anthropic Messages、远端 catalog 说什么 OpenAI，同一个名字两条路径对 `/v1` 的归属互相矛盾（#10992，并让 Nix 构建失败 #10985）；opencode 的 Zen 免费模型不公布额度也不在 429 里返回（#55816），于是用户只能靠「Only free models work with GO」（#55856）反推；hindsight 的 `HINDSIGHT_BANK_ID` 在 `config.json` 存在时被忽略（#5600）、`bank_mission` 从未发往 bank（#5601）；ACP registry 记 OpenCode 1.19.1 而实际在发的是 v2.0.30。**一个名字在几处维护，每处都可能在维护不同的东西。**

2. **model metadata 成了这一期最可能出错的表面，且四个代码项目同时中招。** pi：`max_tokens` 被 4-chars/token 启发式夹到 305 而 prompt 只占窗口 48%（#10988）、Gemini 4 无 `thinkingLevelMap` 时仍发 `thinkingBudget: 0` 招致 400（#11003，P0）、Vertex 的 token 错误从不重试（#10996）。opencode：`ctx.model.transform` 为 config 定义的模型返回占位的 `limit.context` 200000，**基于百分比的插件在 1M 模型上会算错**（#55768）、Go 端点对宣告支持 image input 的模型一律 400（#55785）。hindsight：OpenRouter 的默认 temperature + 强制 `require_parameters` 让拒绝 temperature 的模型（如 claude-haiku-5.5）直接 `No endpoints found`（#5586）。**四个项目没有一个把「模型自报的元数据」当成需要校验的外部输入。**

3. **新增的宿主侧能力在发布当天就与它面向的环境发生协议碰撞。** pi v1.1.0 上线 OSC 7501 program status（终端据此知道 pi 在工作 / 卡在对话框 / 已完成 / 失败），iTerm2 3.7.5 开始支持 7501，而 pi 每条 transcript 消息前插入的 **OSC 133;A 导航标记会让 7501 清除 working/blocked 记录**——重绘时也会插入，因此**终端状态会在没有任何 agent 生命周期事件的情况下自行丢失**（#11017）。同一天 opencode 把 TUI diff 改成默认停靠侧栏、布局按终端宽度自适应。**向终端声明「我在做什么」这件事，两边都在同一天扩大了输出面，而没有先问谁在解析这些序列。**

4. **每一个项目现在都在划「宿主的权限到哪里为止」，但答案方向不同。** opencode #55814：只读 session 通过委派给 `general` 子 agent 拿到完整写权限，**父 agent 自己的 `write` 仍返回 `permission_denied`，但文件已经被改了**——缺的是继承语义，不是判定逻辑。pi #11018：请求一个原子的、非取消的 idle close，**「对 busy 或所有权不明的 session 必须拒绝，而不是取消/排空已接受的工作」**。ACP #2404：**接受建议只填入 composer、绝不发送，用户仍是 transcript 里每条 prompt 的作者**。ACP #2407：**没有 marker 就意味着重放被截断**——把「不完整」变成可检测而非可猜测。**四个答案分别落在策略继承、生命周期所有权、作者归属与完整性信号上。**

5. **ACP 在最热闹的一天彻底安静下来，而它的贡献方式换了。** 上期：8 小时 13 个规范 PR，全部声明 "No wire-format changes"。本期：4 个 commit 全是 registry 版本号推进（OpenCode 1.19.0→1.19.1、Factory Droid 0.242.0→0.242.1）、**0 个新 issue**、tag 停在 v1.11.0、release PR #2379 未合并。但落地的两个 RFD 都换了一种写法：**先在真实 Client 上量出数字，再提规范**——#2407 给出 claude-agent-acp 的历史完整时刻（0.04–0.9s）与作答时刻（空闲 0.5–1.6s、冷启 4.3–4.7s、高负载 8–9s）的分离，以及 codex-acp 每页 100 条、每页一次 RPC 的读法。**「重放什么时候算完」从实现细节变成了一个需要实测才能定义的概念。**

6. **「静默的零」这条线索在 hindsight 上走到了第三段，而开源端已经开始建工具而不只是打补丁。** 第一段（前期）：抽取失败与抽取为空在数据上不可区分。第二段（本期前半）：#5615 让「no facts」散文不再被接受为零事实，#5631 让错误形状的已完成文档被重问一次而不是让整次 refresh 失败。第三段（本期）：**#5626 交付 consolidation eval 套件——发现手段本身被产品化了**；但 #5612 显示这一类还没被覆盖（HTTP 200 + `finish_reason: "error"` 被当成模型没选工具，瞬时传输失败走了模型行为路径，且重试标志在整个 loop 共享）。同一形态在别处是 pi-web 的「不要重扫整个文件」（#1259 冻住 Next.js event loop、#1256 约 1GB RSS）与 opencode 的 #55819（agent-authored 的 watermark-bounded discovery **静默丢掉每周约 500 条全新记录**）。
