## 跨项目观察

1. **"显式状态机"从一种做法变成跨仓库的默认写法，并且开始附带所有权语义。** opencode 本期 37 个 `state machine` 合并 PR 把状态图铺到 desktop / gui-plugins / ui / session-ui / core；pi 则在更小粒度上做同一件事——`ctx.ui.custom()` 的 overlay 以 `blocked` 打开时注册独立的 program status source，被隐藏或被覆盖时**仍然保持阻塞**，关闭一个不影响其它待答问题（#11851）。两侧的共同点不是"画状态图"，而是**给状态指定归属者与结算条件**。

2. **"谁拥有这个对象、它什么时候算结束"成了本期的主线问题。** opencode 的 daemon 引入 owner 交接票据（`prepare_handoff` → 120 秒 ticket → 原子认领，旧 owner 断开不影响新 owner）；pi 的 Chord 定下"reload 只重启受影响的对象，旧工作在旧代码上跑完（5 秒排空上限）"；hindsight 修掉"已删除的 bank 被仍在运行的后台任务复活"。三者是同一个问题的三个切面：**状态必须有明确 owner 与终止条件，否则并发与重启会造出幽灵状态**。

3. **"解耦"在三个仓库指向三个不同的层。** opencode 把官网、文档、config schema、统计数据拆成独立的 Cloudflare Worker（thdxr 一人 12 个合并 PR），并顺手删掉 CLI 的 V1 桥接——**对外的接口面在收缩**；pi 的 p2 改走 Radius 中继，把客户端从"本机进程"里解耦出来；ACP 则维持协议不变、由实现侧推进。**协议层、部署层、运行时层各自有各自的解耦节奏。**

4. **供给侧的客户端差异问题每天都在产生新 issue。** opencode 本期 108 个新 issue 里，Windows 启动的 ResizeObserver 循环风暴与 33–37MB renderer dump（#62206）、Windows "Open in" 拉起 PowerShell 5（#62087）、macOS 粘贴剪贴板图片不附加（#62181）、iOS 多个构建启动即崩（#62213）都是平台差异；pi 侧的 codemode 脚本重复调用同一 tool 24018 次且无 per-script 重复保护（#11858）则是**运行时自保护缺失**。跨仓库的共性是：**同一份代码要同时在多平台、多模型、多运行时下表现一致，而验证矩阵没有跟上**。

5. **"缓存命中"被当作成本问题单独追。** hindsight 的 #6348 / #6357 指出 Anthropic provider 的 reflect tool loop 从不标记 message history，每一轮都按全价计费；pi 侧的 `feat: prompt cache warming in p2`（#11857，未合并）正是在补这一块。**模型侧的计费规则正在把"上下文组织方式"变成产品功能，而不只是实现细节。**

6. **外部贡献者正在用"批量 + 量化"的方式参与，而不是零散提 issue。** hindsight 一位外部贡献者一天提 5 条并附复现步骤（多模态、soft schema、附件回收、检索编排、mental model）；opencode 一位外部 PR 作者一批提 5 个 ACP 修复（#62186–#62191）；pi 一位外部 PR 作者提 3 条 Windows 兼容性修复（#11837 cwd 持久化、#11854 Windows 下杀整棵 bash 进程树、#11852 bash 截断提示报真实尺寸）。**上游正在把"可复现 + 边界清楚"当作合并的前提条件。**
