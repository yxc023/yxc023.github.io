## 本期速览

- **anomalyco/opencode: v2.1 是一次「重写契约」的发布，不是小版本**——`providerState` / `providerResultState` / `state` 三套名字统一为 `native`，`session.compacted` 事件被移除，`Credential.Key.configuration` 迁到 `metadata`，provider compaction 窗口从 `providerContext` 移到 `native.messages`；官方声明「不需要数据库迁移，旧会话/凭证仍可读」；v2.1.0（#57260）同时带来 Windows x64/ARM64 持久 PTY、TUI `todowrite` 任务列表、以及突破 Bun 5 分钟 fetch 死线的长时 TUI 命令。
- **earendil-works/pi: v1.4.0 的主线是「摘要不再有固定输出上限」**——compaction 与 branch summary 改用模型自身的 output limit，`generateSummary()` 的 `reserveTokens` 参数被忽略；同时新增 classifier 的图像输入（Jev / Clef / Clef Omni / Jev 1.14）、从 `models.json` schema 生成的 Models Configuration 参考页、以及 codemode worker 排队而非直接失败。
- **vectorize-io/hindsight: v1.1.0 把「谁调了哪个模型」变成可审计对象**——`ModelCallExtension`（#5936）把每次模型调用的输入与输出都交给扩展，decision model 开始参与 recall 排序（#5284）；**上一期报告标记的「embedding / rerank 从不计量」问题，本期由 `feat(llm-trace)`（#5835）直接回应**。
- **跨仓库的同一件事：模型目录生命周期被三家同时当作一等公民维护**——opencode 隐藏 ChatGPT 账号不可用的 Codex 模型（#58180）、pi 移除上游下架模型与 ChatGPT 账号被拒的 Codex 模型（#11173）、ACP 在 v1.12.0 里「只把已公告下架的模型列为仍不可用」（`530015d`）。
- **跨仓库的同一件事：compaction 的输出上限在同一天被两个 harness 改掉**——pi v1.4.0「summaries without a fixed output cap」与 opencode #57564「compaction summaries use the same model output limit」，两者相隔不到 24 小时落地；上期报告把 compaction 列为三个仓库共同故障面，本期是第一次有实质修复。
- **成本可见性连续第二期被推动**——pi 新增 `totalFromProvider` 标志并改用 OpenRouter 上报的总成本（#11178 / #10286）；hindsight 把 embedding、rerank、decision-model 调用写入请求历史（#5835）。
