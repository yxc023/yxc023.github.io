**社区讨论 / 行业方向：**

- [Hindsight Blog 2026-09-24 "We Added Jev as a Reranker. Here's What We Learned."](https://hindsight.vectorize.io/blog/2026/09/24/adding-jev-reranker-what-we-learned) — 11 分钟，作者 Ben Bartholomew。**核心经验**：
  - Jev 是 TypeSafe 的"System One model"（Kahneman 体系）——只输出 typed answer + 概率，不产文字；Jev 的原语有 Choice / Score / Noul 三种。
  - **错误路径**：① per-candidate Noul（pairwise）→ 200 candidate × 1 round-trip；② 给 Choice 加 "none of these" 选项 → 35/200 题空答；③ 给 Score 加 "nothing" 档 → 7% 空答 + gold retention 0.81→0.65。
  - **正确路径**：**Choice + 整个候选池做 listwise**（"which of these is best" 比绝对打分容易），1 request 即可。LoCoMo 200 题上 listwise vs per-candidate recall@1 = 0.94 vs 0.87，调用次数 ÷30。
  - 配合 **Score cut** 解决"裁剪到第几条"问题（"only the first / the first two / … / all of them"，ordered levels，不需手工阈值）。
  - **默认关闭 cut**——排序与裁剪是两类产品决定：自动 LLM prompt 场景下裁剪收益最大；人类阅读 / 长尾召回场景下不开启。
  - 性能：recall@1 **0.800 → 0.950**（@30 candidates），单 query 耗时 **0.12s → 0.027s**。
  - **部署约束**：Jev 是 hosted third-party API，部分部署形态无法采用。

## 跨项目观察

- **durable / 持久化 agent 运行时是本期最显眼的范式收敛**。pi 的 `pi-durable` 实验线（Packages 19–21：async SQLite / compaction & overflow / extensions + per-conversation agents）走 "Chord + SQLite + 提交后才可见" 的路径；hindsight 的 `bank alias / clone / export-import / rename` 让 bank 可以被零停机搬移；opencode 一直用 SQLite + Drizzle 持久化 sessions + permissions + cost。**三方不约而同把"agent 状态"当成一等资产来设计**——这是过去几个月里"agent 不会失忆 / 不会丢上下文 / 可以跨设备接续"这条产品期望终于出现的工程答案。
- **Jev（TypeSafe 的"System One"模型）在 pi 与 hindsight 之间双向流通**。pi v0.99+ 的 **virtual models** 层用 Jev 做路由；hindsight v0.10.1 / v0.10.2 把同一类模型用作 reranker。**typed answer + calibrated probability** 这种 "no text out" 的原语，正在替代传统 listwise scoring 的 pairwise / pointwise 模式（hindsight 在 200 题 LoCoMo 上 listwise Choice 相对 per-candidate Noul 的 recall@1 = 0.94 vs 0.87，调用次数 ÷30）。同时它也是 hosted 服务的局限——隐私敏感 / air-gapped 场景不能用。
- **Anthropic 鉴权协议栈在 agent runtime 里被强化**。pi v0.99.2 加 `oauth.clientName`、Anthropic workload identity federation（env 三件套）、copy-code OAuth 登录；与 MCP 的 `auth: { provider: "<provider>" }` 组合，**Anthropic SDK 鉴权流程正在变成 agent runtime 的一类基础设施**。这与 OpenAI / Google / 国产各家把鉴权走 provider 自身而不依赖外部 IdP 的趋势不同。
- **MCP 在各家被重新架构**。pi 把 MCP 收进独立 namespace + 沙箱按需加载（`searchTools()` / `describeNamespace()`），并把 MCP 从 prompt 里"撤掉"以减少每条 prompt 的 token 开销；ACP 把 MCP-over-ACP 改为 request-scoped（`#2223`）；hindsight 与 claude-plugin-hub 等社区围绕 MCP 做协议层调整。**MCP 不再只是"挂载第三方工具"，而是 agent runtime 的一等公民——任何一家 coding agent 都需要把 MCP 当作独立子系统设计**。
- **subagents 第一次进入正式 schema**。ACP v1.10.0 / schema-v1.24.0 / schema-v2.0.0-alpha.6 同步发 `#1992`（subagents RFD + schema），并且 v1 stable 与 v2 Draft 都有对应；pi-web 在窗口期内连续 3 个 PR（#990 / #991 / #989）收敛"重启 / 恢复 / 同会话复用"的边界；pi 的 durable 引入 **child tasks** + **owner 概念**。三方对齐——subagents 不再是产品层小优化，而是协议 / 运行时 / UI 三层都要正式表态的概念。
- **Next.js CVE-2026-94545 余波**。pi-web v0.9.2 升到 Next.js 16.3.5 关闭 image 入口是必要不充分，公开修复版本是 16.3.6（hazetec / mallory / ikzero 三方一致），15.x 不受影响；下次升级到 16.3.6 应作为 pi-web 的最近补丁目标。同期 hindsight 已在 9 月 30 日把 `next` 升到 16.3.7（`#5000`）。
- **ACP 生态扩张速度可观**。Reemoat / OctoShell / TermFold / BrokkAi/acp-go 等客户端与语言库进入 registry；ACP TCK 进入文档；NES RFD 被剔除—— ACP 正在从"几个 IDE 集成"扩展为"多端 SDK + 多语言 + 合规测试矩阵"的完整生态。
