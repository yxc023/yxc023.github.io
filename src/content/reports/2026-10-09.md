## 跨项目观察

1. **「秘密不能进构建产物」在本窗口被实证了一次**。pi-web 把三个 Next.js preview secret 烘焙进公开 tarball，且那个值恰好是 Next 跳过 middleware 的凭据，等于给每一个下载过 npm 包的人发了一张绕过密码的通行证；修法不是换个默认值，而是把 secret 的生命周期挪到启动时、并刻意放在 `--ignore-scripts` 绕不过的路径上。同一天 ACP / opencode / hindsight 都在做「把硬编码表换成数据驱动」（`allowAnonymous` 标记、registry 的 CDN 同步、tag scope），两条线合起来的教训是：**凡是能靠「读公开产物」获得的值，就不能当作授权凭证**。

2. **免费额度正在从「福利」变成「故障面」**。opencode 在 24h 内把全部免费模型迁到新的 inference 后端，同一时间用户报出三条不同形态的失败（free usage exceeded、access restricted due to repeated policy violations、Insufficient account funds）；生态里已经长出四条以上「Zen 免费模型二次分发」插件，它们的可用性取决于「空 Bearer + 特定 header」这类实现细节。免费层不再是「模型列表」问题，而是「身份、额度、风控、后端路由」四件事的耦合。

3. **provider 兼容性仍然是 bug 的主要来源，且形态一致**。pi 的 Mistral `timeoutMs` 语义（是整条流还是只等响应头）、pi 的 Claude 5.5 定价（硬编码 vs models.dev 延迟）、pi 的 DashScope quota 限流是否可重试、opencode 的 `service_tier: "ultrafast"`、opencode 的 Gemini 枚举字符串化、hindsight 的 Oracle 时区、hindsight 的 `response_format` 路由——全都是「协议文档写的样子」与「服务端实际行为」不一致。这类 bug 无法靠读文档消除，只能靠真实调用打出来。

4. **「让新条目自动生效」正在成为共识做法**。opencode 用 `allowAnonymous` 标记替掉硬编码模型表（+2 行代码换掉一串模型名）、hindsight 用 per-caller tag scope 替掉按表枚举、ACP registry 把版本同步交给 bot。与之相对的是仍在手工枚举的地方——两者并存，说明迁移还在进行中。

5. **能力探测正在独立成一个跨项目议题**。pi 的 #10672 / #10569（按 OpenRouter key 可用性过滤模型）、#10654（`mcp.json` 里 transport 在环境变量展开前就被解析）、#10699 / #10700（prefix cache 是否还在、`cacheWarming` 是否真的在跑）；opencode 的 #46369（cache-preserving compaction）与 pi 的 #10577 / #8307 同题；hindsight 的 #5275 / #5261（structured-output 的能力边界）。这一类问题的共同点是：模型与 provider 的真实能力（缓存、service tier、schema 支持、限流阈值）没有可靠的探测手段，只能靠运行时试错补齐。

6. **协议生态的重心从「新增实现」转向「宿主多样化」**。ACP 24h 内零新增 agent 实现，两条人工新增全是 messaging（群聊里 @ 别人的 agent）与带审计轨迹的桌面端；hindsight 同时被 Hermes、Paperclip、Grok Bot、Cursor 当作可插拔记忆层，并已从 Hermes 核心树外移到 plugin catalog。两个项目共同说明：协议与插件的**供给侧**已经够多，现在的工作是把它们接到更多类型的宿主上。
