**近 2 天 release 重点：**

- **v1.5.0**（2026-11-02）— AI agent 工具包 v1.5.0（本期唯一一个大版本）
  - **Breaking**：工具入参校验改由 `@earendil-works/pi-schema` 执行。TypeBox 中超出 JSON Schema 的能力（`Type.Refine()`、`Type.BigInt()`、`Type.Undefined()`、codecs、`Format.Set()` formats）不再作用于工具参数
  - **Breaking（行为变化）**：纯 JSON Schema 工具（含 MCP 工具）现在获得与 TypeBox 工具相同的强制转换（例如数字字符串转数字、单值包成数组）；校验失败时模型看到的是 pi-schema 的文案（`- path: missing`、`- limit: expected number, got string`）而不是 TypeBox 的
  - 新增 **GPT-6.1 Terra**（OpenAI / Azure OpenAI Responses / OpenAI Codex 三条通道），带 tool search、会话中途改 thinking level、thinking `off`；Codex 侧提供 500K context window
  - 新增 **Extension update changelogs**：扩展包作者可指定 changelog 路径，pi 在更新后的下次冷启动展示比上次所见版本更新的条目，`collapseChangelog` 可折叠成一行
  - 新增 **流式性能改进**：大 tool call 改为增量解析；代码密集的回复与 tool row 复用高亮与渲染好的 Markdown，不再每次更新重做
  - 新增 **自定义自更新命令**：`PI_SELF_UPDATE_COMMAND` 或全局 `selfUpdateCommand`，可用 wrapper / 其他包管理器更新 pi
  - 新增 `pi.exec()` 的 `maxBuffer` 选项与结果里的 `truncated` 字段；默认上限取 256 MiB 与运行时字符串上限的较小者，超限直接终止进程
  - 新增 `ctx.ui.custom()` 内联组件的 `blocked` 选项，审批类弹窗可以声明"正在等待用户输入"
  - 新增 `Usage.cost.totalFromProvider`，区分厂商实际计费总额与目录估算
  - 变更：**MCP OAuth 登录默认使用 pi 的 Client ID Metadata Document**（授权服务器支持时），否则像 Codex / Claude Code / opencode 一样动态注册客户端；新默认值 `oauth.clientRegistration: "auto"`，`"dcr"` 表示总是注册
  - 变更：**默认 OpenAI 模型从 `gpt-5.5` 改为 `gpt-6.1-sol`**（ChatGPT 登录后未选模型时也用它）；模型目录升级到 models.dev v2
  - 变更：`pi-ai` 不再重新导出 TypeBox，扩展侧从 `@earendil-works/pi-ai` 导入 `Type` / `Static` / `TSchema` 会被映射到 compat 入口 + 内置 TypeBox
  - 移除：原生 OS `sandbox/` 扩展示例及依赖（改用 Gondolin 示例或容器化指南）
  - 安全修复：MCP 登录现在拒绝非 `http:` / `https:` 的授权端点与 OAuth metadata URL（此前恶意 MCP server 可用 `file:` 或自定义协议 URL 交给平台 URL handler）
  - 安全修复：glob 匹配更新，阻断放大型 glob 造成的 DoS；登录弹窗不再打印控制字符（避免终端超链接被截断与转义序列注入）
  - 可靠性修复：`pi.exec()` 不再因命令忽略 SIGTERM 而永远不返回（5 秒后 SIGKILL）；abort bash 命令时改为先杀进程组（不再误跑列表里的下一条命令）；session 写盘失败不再让内存里留下磁盘上不存在的条目（曾导致 resume 后历史与工具丢失）；HTML 导出不再对上千条目的 session 空白页，且现在包含 system prompt 与 tools
  - 性能修复：大的流式 tool call 不再每个 delta 重解析累积参数（曾导致过高 CPU 与内存）；tool row 与流式回复不再每次重绘都重新高亮同一段代码
  - 国际化修复：`tool_search` / codemode `searchTools()` 此前对中日泰等非 ASCII 查询完全找不到结果（分词器只保留 ASCII 字母数字），现已支持任意文字系统并能正确切分无空格文本与 Unicode 等价形式（#10816、#11037）

## 跨项目观察

1. **JSON Schema 从"方向"变成了"有坐标的公共件"，而 breaking 的账单落到了扩展作者头上。** 上一期 pi 用 `pi-schema` 替换 TypeBox 时它还只在 monorepo 里；本期 `@earendil-works/pi-schema` 已发布到 npm（1.5.0，2026-11-02T10:58Z），pi v1.5.0 同日把工具入参校验切过去。但代价是 TypeBox 独有特性失效、报错文案换了一套、连 Nix 打包都因为缺这个依赖而 fail（#11682），pi-web 则必须把它列为固定依赖才能升级。**公共件一旦落地，兼容性成本立刻从核心团队转移到生态。**

2. **"判定依据必须绑定实际会发生的事"这个模式，本周在三个仓库各撞了一次。** opencode 修掉两处 web 权限绕过（URL 规范化、Code Mode 跳转逐跳校验）——之前判定用的是模型写下的字符串；hindsight 让 NaN embedding 在进入 pgvector 前就报错，而不是在绑定时静默丢文档；pi 的 v1.5.0 让工具校验在 pi-schema 上跑并给出路径化的错误信息。**三处的共同点：失败位置从"下游"提前到了"边界"。**

3. **多进程 / 同状态并发，正在成为独立于业务逻辑的一类缺陷。** pi 双进程 resume 同一 session 会分叉并丢分支（#11684）、`.pi/extensions/` 下的测试文件被自动 import 后 `process.exit()` 打死宿主进程（#11691，已两次打挂 pi-web 的服务器）、RPC 进程在目录刷新时被停导致 OAuth refresh token 丢失（#11692）；opencode 并发 plugin 配置更新丢失成功修改（#61298）、同一插件跨位置并发 npm install 报 LockTimeoutError（#61131）。**agent 越来越像一个长期运行的服务进程，而它自己的状态文件却还是单进程时代的设计。**

4. **缓存命中率仍然是用户能直接感知、且最容易被归咎于"钱包"的痛点。** opencode 侧：Go 通道几乎每轮失效（#61276）、经 Claude Agent provider 跑 Opus 5.5 的 CacheX 只有原生 Claude Code 的 1/3.6（#61282）、zen 上超过 256k 上下文缓存塌陷（#58175）；第三方已经指出 Go 通道要求 `x-opencode-session`，会话亲和从"优化项"变成"接入前提"。pi 侧也给出对应修复：pi-web 保证工具顺序与 pi CLI 一致以免提示词变化导致缓存失效（#1481）。hindsight 的对策最直接——补 `session-id` 让一次操作共享 prompt cache（#6267）。**"会话亲和"这个词，已经从三个仓库的 issue 标题里同时长出来。**

5. **免费额度正在变成产品问题而不是运营问题。** opencode 的免费模型（DeepSeek V4.1 Flash）自 10-24 起每天 429、额度重置后几秒内再次耗尽、Go 计划无法使用免费模型、gateway 免费模型 400——这些在 3746 个 open issues 里成规模出现。**开源 agent 用免费模型当默认入口的模式，正在被供给侧卡住。**

6. **协议的"第一轮"是目前最脆弱的一段。** ACP v1.15.1 本身几乎没有新内容，但下游实现里已经暴露出三条"首轮"缺陷：`session/new` 传入的 MCP 工具在第一步丢失、`session/set_config_option` 的回复描述上一个模型、question 工具因文本含 "token"/"secret" 就静默丢弃问题。**这三条都不是协议文本的问题，而是"客户端与 agent 谁负责把第一轮对齐"的分工问题。**
