2. **「不阻塞会话」从工程细节升为产品契约，并且三家给出了三种粒度。** opencode 在同一晚提出 steer 即转后台（#60367）与工具 30 秒自动转后台（#60375），并用 `SessionInfo.time.busy` 暴露“会话在忙什么”；ACP 用 background work RFD（#2452）把同一件事写进协议（tool call 可在 idle 后继续、`state_update.background` 列表、可单独 cancel）；pi 则反向处理——长会话的性能债（#11570 V8 OOM、#11567 全量扫描）仍在被用户量化投诉。**opencode 在往前跑，pi 在补陈账，ACP 在把追不上的语义写成规范。**

3. **「同一能力开两个入口」的维护成本，本周在三个仓库重复出现。** hindsight 的 MCP `recall` 补上 HTTP API 的 `rerank prune/dedup`（#6195，`RerankOptions` 从 `api/http.py` 搬到 `engine/response_models.py`）；opencode 的 schedule 同时服务 CLI、agent 工具与 SDK（#59457、#60137、#60140）；ACP 的同一语义同时要写进 schema、RFD 与迁移指南（#2613、#2615、#2620）。**“多写一份”的成本不会消失，只会从代码转移到文档与参数映射上。**

4. **社区反馈的形状继续分化，而且本轮出现一个值得注意的反差。** opencode 窗口内新增 32 个 issue、关闭 91 个，关闭速度远快于新增速度，但新增内容里开始出现“要内置 free-only 模型过滤”这种**产品诉求型** issue（#60392、#60383），而不是单纯的报错；ACP 合并 PR 翻倍到 59、仍是零外部反馈；hindsight 的 8 个新 issue 里有 4 个来自第三方插件，**全部是集成层的语义错误**。**三家的社区信号分别是“用户在提要求”“用户没出现”“用户在别人的集成里报错”。**

5. **边界项目开始暴露边界问题。** hindsight 的插件生态问题（SecretRef 被当字符串发出 #6201、API 不可达时 retain 被丢弃 #6196、默认 recallTypes 下导入记忆不可见 #6198、Codex OAuth 刷新后 embeddings 401 #6200）都不是核心引擎的 bug，而是**“接口的语义有没有被完整继承”**的问题；pi 的 Windows / WSL 坑（#11588、#11592、#11597）同理。**当一个项目从库变成产品，bug 会从“函数不对”变成“边界不对”。**

6. **“只复用、不新增”正在成为共同的设计偏好。** ACP 的 background work 拒绝新增实体；hindsight 的 rerank 参数从 HTTP 层搬进共享的 response model；opencode 的 `SessionInfo.time.busy`、hindsight 的 `RerankOptions` 都是把新语义压进已有字段或已有类型。**三家都选择了“先压扁语义，再扩结构”。**
