## 跨项目观察

1. **「零 release 日」第一次出现，而开发节奏是本清单里最快的。** 本期 6 个仓库全部没有新版本，但 24 小时内 opencode 合了 14 个 PR、pi-web 合了 17 个 PR。**发布节奏与开发节奏第一次明显分离**：上期是「架构改动日」（pi durable 删 sleep、ACP 从规范里删特性），本期是「纯 commit 日」。对读者的含义是明确的——**当报告里没有 release 时，信号全部在 commit 与 issue 里，去看 `pushed_at` 与 PR 数而不是 tag 列表。**

2. **可观测性第一次作为「显式注入的契约」被设计，而不是全局埋点。** pi 的 `pi-telemetry` README 逐条列出了它**不做**什么：「no exporter, global current-span state, or dependency on a telemetry backend」，`Context.telemetry` 默认 NOOP，用 `withTelemetry` / `traceIn` 显式包装；同一批提交把 durable 的失败面从字符串变成 9 种 typed reason，并让 report 点名是哪个 extension、哪个 `HarnessOptions` 回调出的问题。opencode 同日有机器人开的 `fix(core): log providers removed by policy`（#56905）。**三方都在补同一个东西：「这个进程到底做了什么」的查询面，而且都不打算依赖一个后端 SDK。**

3. **「静默降级」第三次成为主要缺陷形状，而且这一次是跨三个仓库的。** opencode 上期的 #56602（V2 配置静默丢弃 MCP server）与 #56583（CLI 对高版本 DB 报一个不指向根因的错误），本期变成 #56903（`project.open` 从未注册，菜单渲染器把未知 command id 视为永久禁用，File → Open Project 在 Windows 11 上恒灰）与 #56902（provider 配置里新增的模型要重启 service 才出现，catalog 是启动时的快照）；pi 侧同时有 #10074（Anthropic tool call 里 `\uXXXX` 掉了 `u` 变成控制字符，会话在 streaming `edit` 时无限卡住，eyalroth 今天补了 1.3.0 上的数据点）、#10704（`waitForIdle()` 在 settled-handler compaction 完成前就 resolve）、#10956（cacheWarming 的 idle 静默停掉，烧掉约 $500）。**共同点一句话：配置看起来完全正确，功能却不存在，且没有任何一句警告。** 这类缺陷不会自己冒出来，只会被用户逐个撞上——而每一个撞上的用户都会开一个独立 issue。

4. **「一个缺陷类第一次以重复提交的形式出现」是它没被归类的证据。** opencode 的 #54679 / #55081 / #55275 是同一个 bug（V1 的 global project 会话在 V2 的 cwd-scoped 列表里消失），三个人在 10-12 / 10-13 / 10-14 各开一个，措辞各不相同，三个都 closed。加上 #56902 与上期的 #56583（CLI 1.19.3 跑在 Desktop 2.0.32 建的 `opencode.db` 上崩），**V1→V2 迁移的断点不在代码里，而在「谁拥有 `~/.local/share/opencode`」这个没有写下来的约定上。**
