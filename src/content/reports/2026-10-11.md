- `4130bd5` 修复 — `fix(codemode): ignore Node --watch notifications from the worker` (@Armin Ronacher, 2026-10-10)。Node 24/26 的 `--watch` 会往 worker channel 发 `watch:import` / `watch:require`，导致整次运行以「损坏的 bridge」失败（nodejs/node#65044，closes #10725）。
- `cb43754` durable 性能 — `fix(durable): scheduler no longer visits every live task on each pass` (@Mario Zechner, 2026-10-10)。n 个 held task 的链约 n³ 步（500 个 12 s，20,000 个跑不完）；改为在 open 时重建的内存索引承载每趟候选：`#below`（围绕活工作向下的所有权树）、`#intent`（从有取消意图的任务向下走，不进入另一个这样的任务，因此最近的取消者仍然决定原因）、`#unloaded`、`#finalizeChecks`、`#runnable`、`#waiters`，**没有任何走查会递归**。语义不变。结果：500 → 50 ms，20,000 → 1.5 s，8000 并行嵌套调用 18.8 s → 9.2 s（余下时间花在嵌套调用索引的文档复制上）。
- `4ac0bd8` durable 结构 — `feat(durable): one document per nested call; TaskRuntime.ownedTasks()` (@Mario Zechner, 2026-10-10)。`NestedCallsDoc`（每个 caller 一个索引、每次嵌套调用一个 key、每次 admission 都复制）与 `NestedResultDoc` 合并为 `NestedCallDoc`（`pi.tool.nested-call`），task 作用域、key 是调用方的 key、存 `{ taskId, result? }`；`TaskRuntime.ownedTasks(context)` 从调度器索引返回该 task **直接拥有**的存活任务副本（不论是哪个 invocation 建的），工具调用结算时中止其中的活嵌套调用；task memo 记住「某次尝试里做过嵌套调用」的叶子，结算时无需扫描 `pi.live`。8000 并行嵌套调用 9.2 s → 2.7 s，且随规模线性。
- `ea448f4` durable 内存 — `fix(durable): bound the scheduler's ownership indexes by live work` (@Mario Zechner, 2026-10-10)。此前调度器会保留它见过的每一条对话边，以及 conversation owner、chain load、known task 的 owner 上方所有已结束任务，**整个进程生命周期**；现在 owner edge 或已结束任务的所有权只在「`#below` 里它下面还有东西」时保留，无用的节点在每次发布后入队清扫（或在 Session 线上的 sweep job 里做），从不在操作过程中做。10,000 次 ended subagent 循环挂在活着的 parent 下：从 10,000 个 settled task + 10,001 条边降到 **0 和 1**；之后往一个旧的 subagent 对话里发消息时从 storage 读 7 条记录而不是 5 条。
- `c5f5b32` MCP 安全修复 — `fix(mcp): reject iss when no authorization server metadata was discovered` (@Armin Ronacher, 2026-10-10)。没有发现 metadata 时就没有 issuer 可与 RFC 9207 的 `iss` 参数比对，于是这项检查被跳过，**恶意 MCP server 可以收到来自另一个授权服务器的 authorization code**；现在在 code 交换之前直接拒绝该响应。由 Alexios Stefanopoulos（@AizenvoltPrime）报告。
